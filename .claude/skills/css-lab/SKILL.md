# css-lab 태그 사용법

블로그 본문(마크다운)에 쓰면 **단계 라디오 + 실제로 도는 데모 + 현재 단계 CSS**가 함께 나온다. 독자가 단계를 누르면 그 자리에서 스타일이 바뀐다.

자바스크립트는 한 줄도 안 나간다. 전환은 `:has()`가, 격리는 `@scope`가 한다.

## 최소 템플릿

편집기 본문에 그대로 붙여넣고 채우면 된다.

```
<css-lab>
<css-html>
<button class="btn">눌러봐</button>
</css-html>
<css-step label="1. 뼈대">
.btn { padding: .8em 1.8em; border: 0; border-radius: 10px; background: #1a1a2e; color: #fff; }
</css-step>
<css-step label="2. 색">
.btn { background: linear-gradient(120deg, #6a5cff, #b06cff); }
</css-step>
</css-lab>
```

## 태그 셋

| 태그 | 몇 번 | 하는 일 |
|---|---|---|
| `<css-lab id="...">` | 데모마다 1번 | 껍데기. `id`는 **선택** — 안 써도 자동으로 갈린다 |
| `<css-html>` | 안에서 1번 | 무대에 세울 마크업 |
| `<css-step label="...">` | 여러 번 | 단계 하나. `label`이 버튼에 찍히는 이름 |

`<css-lab code="off">`로 쓰면 아래 CSS 코드 패널이 안 나오고 무대만 남는다. 코드를 읽히려는 게 아니라 결과물만 보여줄 때 쓴다. 단계 라디오는 그대로 뜬다.

## 단계는 누적된다

각 `<css-step>`에는 **그 단계에서 새로 얹는 CSS만** 쓴다. 앞 단계를 다시 적지 않는다.

3번을 고르면 화면엔 1+2+3이 겹친 상태가 나오고, 코드 패널엔 **3번에 쓴 것만** 보인다. 그래서 "이 줄이 이 변화를 만들었다"가 한눈에 들어온다.

## 안쪽은 그냥 HTML과 CSS다

`<css-html>` 안은 평범한 HTML, `<css-step>` 안은 평범한 CSS다. `::before`, `:hover`, `:has()`, `@media`, `@keyframes`, `@property`, CSS 변수 전부 그대로 쓴다. `<style>` 태그는 쓰지 않는다 — `<css-step>`이 그 역할이다.

**들여쓰기·줄바꿈·빈 줄을 원문 그대로 쓴다.** uiverse처럼 여러 줄로 펼쳐진 CSS를 손질 없이 복사해 붙이면 된다.

```
<css-step label="1">
@media (min-width: 40rem) {
    .btn {
        padding: 2em;
    }

    .btn:hover {
        opacity: 1;
    }
}
</css-step>
```

한 줄로 압축하든 4칸으로 펼치든 결과는 같고, 코드 패널에도 쓴 모양 그대로 나온다. `remarkCssLab` 플러그인이 이 구간을 원본 문자열에서 되살리기 때문이다 — 안 그러면 마크다운이 빈 줄에서 블록을 끊고 뒷부분을 문단·코드블록으로 재해석해서, 쓴 적 없는 `<p>`·`<pre>`가 CSS에 섞인다.

## 규칙 5개

**1. 여는 태그와 닫는 태그는 다른 줄에 둔다.**
한 줄에 쓰면 마크다운이 인라인으로 보고 데모를 `<p>` 안에 가둔다.

**2. 자기닫기는 쓰지 않는다.** `<div />` ✗ → `<div></div>` ✓
HTML 파서가 `/`를 무시해서 **뒤따르는 문단을 통째로 데모 안으로 삼킨다.** JSX 습관을 조심할 것. `<img>`, `<br>` 같은 void 요소는 원래대로 괜찮다.

**3. 무대 자체를 꾸밀 땐 `:scope`를 쓴다.**
`@scope`가 무대 안쪽만 훑기 때문에 `body`, `html`, `:root`는 안 먹는다.
```css
:scope { background: #14142b; padding: 3rem; }
```

**4. `@keyframes` 이름은 데모마다 다르게 짓는다.**
애니메이션 이름은 문서 전역이라, 같은 글의 다른 데모가 `spin`을 쓰면 나중 정의가 이겨서 엉뚱한 데모가 따라 돈다. `angle-lab-spin`처럼 데모 이름을 섞는다.

**5. prose가 건드리는 태그를 꾸밀 땐 선택자에 태그를 붙인다.**
대상: `a ul ol li img table th td code pre blockquote hr h2 h3 strong`
```css
.demo  { color: green; }   /* ✗ (0,1,0) — 블로그 본문 스타일에 진다 */
a.demo { color: green; }   /* ✓ (0,1,1) — 이긴다 */
```
데모가 `.prose-post` 안에 살기 때문에 생기는 조건이다. uiverse 컴포넌트는 대개 `button`·`div`·`span`·`input`·`label`·`svg`라 해당 없는 경우가 많다.

## 데모를 나눌까, 단계를 늘릴까

| | 언제 |
|---|---|
| `<css-step>` 늘리기 | **같은 걸 계속 다듬는 중** — 배경색 → 그라데이션 → 각도 |
| `<css-lab>` 새로 | **주제가 바뀜** — 배경 얘기 끝, 이제 그림자 |

한 글에 데모 3~5개, 데모마다 단계 3~4개 정도가 읽기 편한 밀도다. 라디오가 8개 넘어가면 무슨 얘기 중인지 흐려진다.

데모끼리는 CSS를 공유하지 않는다. 각자 독립된 무대라 새 데모의 1단계에는 필요한 기본 스타일을 다시 적어야 한다 — 대신 독자가 글 중간부터 읽어도 그 데모만 보고 이해할 수 있다.

## JS 없이 되는 상호작용

대부분의 CSS 컴포넌트는 자바스크립트가 필요 없다.

- **누르는 동안만 반응** → `:hover` `:active` `:focus-visible`
- **클릭 상태가 남아야 함** → 숨긴 `<input type="checkbox">` + `:checked`. 토글·스위치·탭·별점·햄버거가 전부 이 패턴
- **부모/조상까지 바꾸기** → `:has()`
- **모달·드롭다운·툴팁** → Popover API (`popovertarget`)
- **아코디언** → `<details>`
- **계속 도는 애니메이션** → `@keyframes`

**JS가 필요한 선**: 값을 읽어 반영(슬라이더 → 숫자), 계산·누적(카운터), 타이머·비동기, DOM 생성. CSS는 "상태에 반응"은 하지만 "값을 읽어 계산"은 못 한다.

무대 안에 체크박스를 쓸 땐 `id`/`name`에 접두사를 붙여 단계 라디오와 겹치지 않게 한다.

## 증상별 진단

| 증상 | 원인 |
|---|---|
| 데모가 통째로 안 보인다 | `<css-step>`이 하나도 없다 (없으면 아무것도 안 그린다) |
| 뒤 문단이 데모 안으로 빨려 들어갔다 | 자기닫기(`<div />`)를 썼거나 닫는 태그가 빠졌다 |
| 데모 주변 여백·정렬이 이상하다 | 여는·닫는 태그를 한 줄에 써서 `<p>`에 갇혔다 |
| 단계를 눌러도 화면이 같다 | 값이 시각적으로 너무 비슷하다. 색 대비·두께를 키워 확인 |
| hover 단계인데 변화가 없다 | 마우스를 올린 채로 단계를 바꿔야 보인다 |
| 두 데모가 같이 움직인다 | 내용이 완전히 같아 id가 겹쳤다 → `id`를 서로 다르게 |
| 엉뚱한 데모가 따라 돈다 | `@keyframes` 이름 충돌 (규칙 4) |
| 링크·목록 색이 의도와 다르다 | prose 리셋에 졌다 (규칙 5) |
| `body {}`가 안 먹는다 | `:scope`로 바꾼다 (규칙 3) |
| 스타일이 통째로 안 먹는다 | 구형 브라우저. `@scope`·`:has()`·`@property` 미지원이면 조용히 무시된다 |
| `syntax: "<...>"`가 깨진다 | 파서가 꺾쇠를 태그로 읽는 자리다. 되살리는 처리가 있지만 실패하면 알려줄 것 |

## 쓰는 흐름

1. 관리자로 로그인하고 `/blog` 목록 상단의 **새 글**, 또는 `/admin/posts/new`
2. 본문에 마크다운과 함께 붙여넣는다
3. **미리보기 탭**에서 확인 — 실제 글과 같은 렌더러라 결과가 어긋나지 않는다
4. 저장

## 코드 위치

| 파일 | 역할 |
|---|---|
| `views/blog/components/CssLab/CssLab.tsx` | 라디오·무대·코드 패널 렌더. 무대 높이(`min-h-48`)도 여기 |
| `views/blog/lib/buildCssLabStyle.ts` | `@scope` 스타일시트 조립, 누적 게이트, prose 리셋 |
| `views/blog/lib/markdownComponents.ts` | 태그 → 컴포넌트 맵 |

작성한 CSS는 **한 글자도 변형되지 않는다.** 앞뒤에 `@scope (...) {` 와 `}` 를 붙여 `<style>`에 넣을 뿐이고, 렌더링은 브라우저 CSS 엔진이 한다. 그래서 CSS 문법 오류는 잡아주지 않는다 — 브라우저가 그 규칙만 버리고 나머지는 그대로 돈다.
